## ADDED Requirements

### Requirement: A frozen evaluation set
`backend/eval/issues/` SHALL hold `complaints.csv` and `labels.csv`. Each label row is `complaint_id`, `main_category`, `other_categories` (a `;`-list, empty for single-issue complaints) and `split` (`dev` or `final`). The set contains:
- about 30 **two-issue** complaints with known pairs, including Dev A's 6 mixed tests. They are generated by `backend/eval/make_issues.py` from labelled training complaints, with a second issue written in a different category in messy customer style.
- about 30 **tricky single-issue** complaints using words that belong to other categories ("caj" meaning charged, "kad ATM", "twice", "hotline" used only to report).

Once committed, the set SHALL NOT be edited to suit the prompt. Half of each kind is `dev` (may be read while tuning); the other half is `final` (only checked).

#### Scenario: Final half untouched
- **WHEN** the prompt is tuned
- **THEN** only `dev` results are looked at, and `final` is run once, for the merge gate

### Requirement: Report
`python -m backend.eval.issues_eval [--split dev|final|all] [--extra train|messy|test]` SHALL report:
- **caught:** two-issue complaints whose expected other category was kept
- **false flags:** single-issue complaints with any kept other issue
- the cost and the p95 latency of the issues call

It SHALL write each flag with its quote to a CSV for reading. With `--extra`, it runs on those sets too: every flag on training or messy complaints is a false flag (one labelled issue each), and test-set flags are listed for reading.

#### Scenario: Reading the flags
- **WHEN** the report runs with `--extra train`
- **THEN** it prints the number of flagged training complaints and writes each one with its category and quote

### Requirement: Merge gate
The change SHALL merge only when all of these hold:
- **final split:** caught ≥ 80% of the two-issue complaints, and false flags ≤ 1 of the single-issue ones
- **training (1,750):** at most 1% flagged, each read; the score is unchanged (99.94) on the scored fields
- **messy (42):** at most 1 flagged
- **test (750):** every flag read and judged plausible, and no scored field changed in `predictions.csv`
- `scoring/api_check.py`: 100.0 with 9/9 probes, and `--n 20` with every complaint done well inside 120 s
- the full test suite passes

If the gate isn't green by 14:00 on Day 2, the change isn't merged, and the demo uses PLAN.md's prepared answer.

#### Scenario: Gate fails on false flags
- **WHEN** the final split shows 3 single-issue complaints flagged
- **THEN** the change isn't merged, and the prompt is revised against the dev half only
